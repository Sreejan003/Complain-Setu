# Plan 04-01: Real Database Integration (PostgreSQL / Supabase)

## Objective
Establish a production-ready database architecture: reconcile SQL schemas with TypeScript models, create versioned database migrations including the missing `documents` table, implement an `IRepository` abstraction with both `PostgresRepository` (connection pooling, parameterized queries, transactions) and `JsonRepository` (development/test adapter), provide an active migration runner (`npm run migrate`), and replace misleading health-check logic with actual live database pinging.

## Tasks
1. Reconcile SQL schema in `database/migrations/001_initial_schema.sql`:
   - Include tables: `profiles`, `bureaus`, `institutions`, `complaints`, `case_assignments`, `case_history`, `case_transfers`, `related_cases`, `overlap_alerts`, `notifications`, `audit_logs`, and the missing `documents` table.
   - Reconcile ID formats, foreign keys, constraints, and indexes.
2. Create `database/migrations/002_rls_policies.sql` for Supabase PostgreSQL Row Level Security.
3. Define `IRepository` interface in `backend/src/db/repository.ts`.
4. Implement `PostgresRepository` in `backend/src/db/postgresRepository.ts` with pg connection pool, transaction support, and active `healthCheck()`.
5. Implement `JsonRepository` in `backend/src/db/jsonRepository.ts` adhering to `IRepository`, with explicit development-only mode warnings.
6. Create repository factory in `backend/src/db/index.ts` and update `store.ts` to export repository singleton.
7. Create migration runner `backend/src/db/migrate.ts` and add `"migrate": "tsx src/db/migrate.ts"` to `backend/package.json`.
8. Update `adminRouter.get("/system-status")` to execute actual database connection check.

## Verification
- Migrations parse as valid SQL.
- `PostgresRepository` compiles and types match `IRepository`.
- `backend/package.json` includes `npm run migrate`.
- `npm run build` in `backend` succeeds.
- Database health check accurately reflects connection state.
