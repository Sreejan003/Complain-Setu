# Plan 06-01: SLA Scheduling & Notifications Hardening

## Objective
Harden the AICTE Statutory SLA Monitor engine: correct date boundary math to prevent premature overdue marking on due date, implement bounded paginated dataset processing, enforce idempotent notification deduplication, and add concurrency lock protection.

## Tasks
1. Correct date boundary calculation in `backend/src/services/slaScheduler.ts` using normalized UTC calendar dates (`diffCalendarDays`).
2. Implement paginated batch retrieval in `runSlaEvaluationCycle` to scan all active complaints across any number of pages.
3. Enforce notification deduplication against both persisted store notifications and notifications created during the active cycle.
4. Add execution concurrency lock (`isCycleRunning`) to prevent overlapping executions.
5. Provide structured logging for cycle execution, overdue counts, auto-escalations, and skipped duplicates.
