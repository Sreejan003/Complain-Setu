# Phase 8 — bounded ingestion and adapter framework

Completed without connecting live systems or registering complaints automatically. CSV and XLSX uploads share a persisted preview/commit pipeline with internal email simulation. Every successful row creates an unresolved intake draft with original wording, Unicode language metadata and import-run/row provenance. Institution matching returns authorized ranked candidates; selection and supervised registration remain human steps. Existing registration subsequently performs overlap review. Importing never bypasses sensitivity, lifecycle or case permissions.

Limits:2MiB input,200 data rows,32 columns,20,000 characters/cell,40,000-character CSV record. XLSX accepts one visible sheet. Yauzl reads ZIP entries lazily, validates declared/actual sizes and strict names, with64-entry,4MiB-entry,16MiB-total and compression-ratio limits before ExcelJS decoding. Macros, embedded media/files, external references, unsupported workbook parts, XML entities/DTD and oversized dimensions are rejected. Formula/complex/date-valued spreadsheet cells produce row errors; dates must be ISO text. UTF-8 CSV strings are literal, including formula-like text; originals are retained. Error CSV contains only row numbers, statuses and fixed codes, without echoing source values. CSV record numbers are logical records; XLSX errors retain worksheet row numbers.

Partial success is explicit: valid new source references become drafts, failed rows stay in the run, unexpected storage errors roll back the transaction. Batch keys are private to their creator and bound to a stable parsed-content digest. Identical replay returns its prior run; conflicting payloads are rejected. Immutable receipts uniquely bind normalized source-channel/reference to a draft. Repeated/concurrent commits and corrected batches reuse successful rows; changed content or another owner's reference returns a generic unavailability error without another record ID. Corrected failed rows require a new batch key. Configuration changes require a fresh preview; stale versions are rejected. Imported records later sealed outside the owner's access hide the entire affected run, list entry and error download. Current role/Bureau/region and ownership are rechecked.

Protected endpoints are under /api/imports: capabilities, CSV/XLSX templates, inspect, preview, email-simulation, private run history/details/errors.csv and versioned commit. CSS/CPGRAMS POST adapters return501 disabled. Internal email schema internal-email-fixture-v1 is not an official contract and accepts no attachments. No mailbox, government integration, notification or external translation is connected. Frontend /imports is linked from Case Intake and uses existing UI components, field mapping, preview, explicit commit acknowledgement, history/error downloads and a labelled email simulator. All23 locale packs include English fallback keys; no translation approvals changed.

Migration009_ingestion.sql adds import runs/receipts, owner/batch and source/reference uniqueness, FKs/indexes and immutable receipt triggers. Commands: npm run migrate:plan --prefix backend (listing only), npm run migrate --prefix backend (explicit configured PostgreSQL authority after backup). Migration was executed only in disposable native PostgreSQL. JSON remains development/test storage. No operational backfill/reset was performed.

Important files: backend models/ingestion.ts, services/importParsing.ts and ingestion.ts, routes/ingestion.ts, Store/operationalPostgres projections, intake.prepare validation extraction, models/intake provenance, server wiring, migration009; frontend ImportWorkspace, IntakeWorkspace link, API helpers, route/access and23 complaint resource files.
